# 分析师系统修复实现计划

依据用户已批准执行的《分析师与模型严格审查》，完成当前8类P1、2类P2。保留已导入数据、已保存画像、密钥及未跟踪文档；每次既有源码改写前保存唯一备份。默认在当前已验证的项目环境集成，源代码职责分开，避免并行编辑同一文件。

## 设计与接口

1. `app/tools/selection_plan.py`：统一解析当前问题，区分申请人事实、岗位要求、排除条件、地区、考试类型、年度、代码与主要任务。公开 `build_selection_plan(payload)->dict` 和 `apply_selection_plan(payload)->payload`；保留原始问题，不把“不限专业岗位”改成用户专业不限。专业要求层级/不限专业、学历上限等任务约束放入 `selection_constraints`；模型解析信息不能直接覆盖资格事实。
2. `app/tools/job_category.py`：修复机关地名歧义、前后置否定、并列、以外等作用域；公安县税务不能判为公安。保留现有公共接口。
3. `app/services/analysis_grounding_service.py`：以岗位字段为准校验模型卡片和正文，移除“固定八段+关键词命中即整篇丢弃”的门槛。数值、资格、证据缺口和承诺性结论需要校验；谨慎否定句可保留。公开 `ground_card(payload,job,analysis,fallback)->(dict, metadata)`、`ground_report(payload,jobs,report,fallback)->(str,metadata)`。
4. `app/services/llm_service.py`：结构化失败原因、每阶段预算和模型调用状态；避免逐卡调用耗尽报告预算。保留旧接口兼容，新增阶段控制与运行度量，不读取或输出密钥。
5. `app/services/selection_decision_service.py`：资格硬筛后对有限候选池调用带公开skill的模型，返回候选ID、排序、取舍依据和证据引用，校验只能引用给定候选。公开 `select_candidates(payload,candidates,limit)->(jobs,metadata)`。失败返回确定性候选并标明回退，禁止越过地区、资格及类别门槛。字段受grounding二次核验。
6. `app/agents/exam_agent.py`：统一入口先应用计划，明确代码优先旧卡片，推荐附带分数条件仍走推荐；推荐获取扩大的候选池后由selection service取舍。所有详情/追问执行同一资格核验，问能不能报时列出已知不满足项；模型正文真正进入可见回答。统一grounding和运行元数据。
7. `app/tools/job_tool.py`：增加内部候选池参数（普通API默认数量兼容），岗位要求约束与个人专业分离；统一单岗位行政地点证据，显式代码跨地区查询标注范围，不以备注冒充工作地点。
8. 响应schema和前端：展示有效条件、模型/规则/混合状态、skill是否参与比较、候选池范围、回退原因。旧接口字段兼容。

## 实施次序与验证

- 独立模块并行完成：语义计划/类别；事实grounding/调用预算；skill候选选择。各自新增失败用例后实现，不编辑其他任务拥有文件。
- 主集成负责agent、job_tool、schema、前端；逐项复现审查反例转为通过的验收测试。
- 必测：排除法学不改变软件工程；非应届/往届正确覆盖旧身份；国考/省考与年度；不限专业岗位约束；复合推荐查分不扩大城市或类别；新代码不被旧卡吞；公安县税务和否定句；未知报名竞争分数不编造；正确谨慎正文保留；追问正文及已知不符合；skill确实改变合格候选间取舍且拒绝外部ID；慢模型预算及来源显示。
- 执行现有全部Python/JS测试、语法检查、源码读回、独立最终代码复核；适当真实HTTP验证。真实模型若调用，仅使用必要的少量请求，不改变用户配置。
- 验收通过后重启当前服务、只提交本次文件并同步已授权GitHub；交付逐项状态、改动字符数、备份和限制。不能因局部测试通过就宣称所有智能场景已覆盖。

## 已授权的实现判断

候选池采用可配置上限并明确展示覆盖范围，避免宣称模型比较了所有全国岗位；硬筛之前不能只截取旧Top5。优先给最终可见回答分配预算，卡片优先使用结构化事实与批量结果，不逐卡重复调用模型。保留可查看但不符合的详情岗位，与可推荐岗位明确区分。
